# Moci 编程性能

适用于战斗 advance/render、武器效果、船插、AI 与频繁范围查询。优先减少工作量，再优化单次数学运算；以保持玩法、目标集合与时序为前提。只优化本次涉及的路径，不为性能建议顺带重构其他系统。

## 用户偏好（2026-10-24）

渲染性能问题优先在渲染层解决：按适用性采用批量绘制、GPU instancing、可复用缓冲区和视口裁剪，不改命中、伤害、动画、卡肉、时流等业务逻辑。保留用户已调好的数量、大小、颜色、速度和寿命；减少粒子数量等画面取舍需有本次明确要求。实例化不是固定优选，仍需核对硬件能力、降级路径和实际瓶颈，不承诺未经实测的性能提升。

## 局部查询与现有工具

先读工程 src/data/scripts/util/Moci_Util.java。本页方法与限制于 2026-10-24 核对；实现变化后重新确认，不只依据名字或注释。

| 需求 | 已有工具 | 使用的空间索引 |
|---|---|---|
| 导弹 / 非同 owner 导弹 | getMissilesInRange / getEnemyMissilesInRange | getMissileGrid |
| 所有弹丸（含导弹）/ 非同 owner 弹丸 | getAllProjectilesInRange / getEnemyProjectilesInRange | getAllObjectGrid，再筛 DamagingProjectileAPI |
| 舰船 / 非同 owner 舰船 | getShipsInRange / getEnemyShipsInRange | getShipGrid |
| 小行星 | getAsteroidsInRange | getAsteroidGrid |
| 矩形附近的导弹 / 弹丸候选 | getMissilesInRect / getAllProjectilesInRect | 对应网格；调用方补精确几何检测 |

局部半径查询可沿用已有方式：以 center 为中心，宽高均为 radius * 2f，调用 getCheckIterator；遍历候选并做类型、在场、过期/残骸、阵营等筛选，再判断圆形范围。优先使用更具体的网格，只有需要混合实体时才用全对象网格。

网格负责缩小候选集合，不能替代圆形距离、线段/旋转矩形、碰撞边界与护盾的精确检测。当前两个 InRect 工具只筛选类型和实体状态，未逐项验证精确矩形；不要直接把返回列表当作已命中目标。圆形工具按中心点距离筛选；若需求是船体边缘进入范围，必须另行核对碰撞半径/边界及查询区域的覆盖。

保持调用方原有筛选语义。当前 getEnemy*InRange 的“敌方”实现只是 getOwner() != owner，未进一步区分盟友或中立；舰船工具排除残骸与不在场实体，弹丸工具排除过期与不在场实体。不要因换工具无意增减目标，或重复把已包含的导弹再次加入伤害结算。

不要看到 WithinRange 就认定用了网格：当前 getProjectilesAndMissilesWithinRange、getEnemyProjectilesAndMissilesWithinRange、getShipsWithinRange 仍含全列表扫描；最后一个还具有排除穿梭机等原有语义。替换前逐项核对，而不是全局替换名字。

当前 Grid 圆形工具仍会创建返回 ArrayList，并使用 Vector2f.sub(..., null).length() 创建临时向量、计算开方。它们可减少候选遍历，但不是“零分配/无开方”接口。热路径若只需判断存在、选最近或就地处理，可在语义一致且任务需要时直接遍历网格候选并早退，避免先建完整结果列表；普通调用继续优先复用现有工具，避免重复维护多套实现。

本地 API starfarer.api/com/fs/starfarer/api/combat/CollisionGridAPI.java 明确提醒：大范围查询时列表遍历有时更快。网格也不保证固定复杂度；查询覆盖大部分战场或候选密集时，对比实际查询频率、候选数量与耗时，再决定，不自行另建重复维护的空间索引。

## 距离与重复计算

只判断非负半径内外或比较最近目标时，优先使用平方距离，半径平方放在循环外：

```java
float radiusSquared = radius * radius;
// 候选循环内，targetLocation 为已取得的位置。
float dx = targetLocation.x - center.x;
float dy = targetLocation.y - center.y;
if (dx * dx + dy * dy <= radiusSquared) {
    // 保留原有处理。
}
```

保留原来的 < / <= 边界，并确保半径符合原输入契约；负半径直接平方会改变语义。避免用创建临时向量再 length() 的方式仅判断范围。需要真实距离做线性衰减、单位向量或显示时，先筛候选，再计算必要的开方；零长度归一化需单独处理。不要把实际距离替换成平方距离而改变伤害曲线，也不要删除为保持分布而使用的 sqrt(random) 等计算。

同一非零除数在循环或多次计算中保持不变时，可把 inv = 1f / divisor 移出循环，内部乘 inv。除数变化时更新倒数，处理原有零值约束；浮点舍入可能不同，涉及阈值/伤害需检查结果。整数除法具有截断语义，不能改为浮点倒数乘法后视作等价。常量运算可能已由编译器优化，不承诺手写乘法总更快。

只算一次能复用的同帧数据：位置、半径平方、固定系数与同一候选查询。不要把会变化的属性误当常量，也不要为省计算缓存已经失效的位置或属性。

## 更新频率与回调

- 单次命中、开火、销毁等行为优先使用已有事件回调，避免每帧扫描全场来找刚发生的事件。
- 目标重新选择、环境统计等允许延迟的工作可用 IntervalUtil 或累计经过时间触发，并错开多个实例的触发时刻，避免同帧集中扫描。间隔由行为允许的延迟决定，不强制固定值。
- 碰撞、拦截、贴近触发与高速弹体检测不能单纯降频；必要时保留逐帧精确检测，或采用经过验证的扫掠检测。降低扫描频率前检查漏判与反应延迟。
- 按实际传入 amount 推进时间，不按固定帧数计时；保留暂停及项目既有时间流速语义。粒子按 rate * amount 累积生成，需要准确数量时保留小数余量并考虑单帧生成上限；不要把每帧固定数量或每帧最多触发一次的概率法当作所有场景的等价替代。
- render 复用已准备好的状态；稳定的随机角度/偏移初始化一次，避免渲染里重复搜索、读配置或重建布局。不要把必要的逐帧动画计算一概降频。

## 分配、缓存与日志

- 高频循环尽量直接算 dx/dy、复用明确归属的临时数据，减少不必要的 Vector2f、列表副本、装箱、字符串拼接及中间集合。普通低频代码保留清晰实现，不无条件禁用某种语法或引入对象池。
- 只需存在性或最优目标时用早退/单次选择，避免收集全部候选再排序。先做廉价的状态、类型、阵营与粗范围筛选，再做昂贵碰撞计算；保持原有副作用和选择规则。
- 缓存按武器、舰船或本场战斗生命周期保存，并明确创建、更新、失效与清理时机；实体死亡、移除、变形或退出战斗时按用途处理。避免静态容器跨战斗持有 engine/ship/projectile 引用。
- 缓存目标每次使用前核对有效性；位置/属性缓存按需要刷新。保存 API 返回的可变 Vector2f 前确认需要引用还是快照，不修改引擎借出的状态。复用列表前确认调用方不会持有或同时使用它，不能清空共享的引擎列表或长期保存网格迭代器。
- 配置解析与资源查找放在适当的初始化/刷新节点。每帧日志改为状态变化、事件、一次性提示或限频统计；遵守项目现有显式开关，不以 devMode 为前提。

## 如何判断优化有效

先核对目标集合、范围边界、阵营、残骸/过期处理、暂停/时间流速、触发次数与伤害结算是否保持一致。网格变更尤其检查区域边缘、大舰体、模块和高速弹体。

确需评估收益时，在可比较的场景和负载下观察查询次数、候选数量、总耗时/帧耗时及对象分配；避免用单次计时或每帧日志证明效果。分别检查局部密集与大范围查询。编译通过只说明可编译，静态检查不证明帧率提高；尚未测量时报告采用了什么减少开销的方式，不声称具体提速比例。
